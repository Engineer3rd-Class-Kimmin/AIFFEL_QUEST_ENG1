### Q1. `.pth` 파일만 전달했을 때 상대방이 모델을 바로 사용할 수 없는 이유는 무엇입니까?

`.pth` 파일에는 주로 학습된 모델의 가중치가 저장되어 있으므로,
모델 구조, 실행 환경, 필요한 라이브러리 등이 함께 필요합니다.

### Q2. 모델 학습(Training)과 모델 배포(Serving)의 핵심 차이는 무엇입니까?

Training은 데이터를 이용하여 모델을 학습하는 과정이고,
Serving은 학습된 모델을 실제 사용자가 사용할 수 있도록 제공하는 과정입니다.

### Q3. 모델 배포에서 사용자와 서버가 소통하는 방식은 무엇입니까?

사용자가 HTTP를 통해 API 서버에 Request를 보내면,
서버가 모델을 실행하고 결과를 Response로 반환합니다.

## 섹션 2. 환경 세팅

### Q1. 가상환경 없이 `pip install`을 하면 패키지가 어디에 설치됩니까?

시스템 Python 환경에 설치됩니다.

`pip freeze`는 현재 환경에 설치된 패키지와 버전을 모두 출력하고,
직접 작성한 `requirements.txt`는 프로젝트에 필요한 핵심 패키지만 관리할 수 있습니다.

`requirements.txt`를 공유합니다.

## 섹션 3. RESTful API

### Q1. 모델 추론 요청에 GET이 아닌 POST를 사용하는 이유는 무엇입니까?

모델 추론에 필요한 JSON, 이미지, 텍스트 등의 입력 데이터를
Request Body에 담아 서버로 전달하기 적합하기 때문입니다.

### Q2. 상태 코드 `422`는 어떤 상황에서 발생합니까?

요청 데이터가 서버에서 요구하는 데이터 형식이나 검증 조건에 맞지 않을 때 발생합니다.

### Q3. `requests.post(url, json=data)`에서 `json=` 파라미터는 무엇을 합니까?

Python 데이터를 JSON 형식으로 변환하여 HTTP 요청 Body에 넣어 전송합니다.

### Q4. Python의 `True`는 JSON에서 어떻게 표현됩니까?

`true`로 표현됩니다.

## 섹션 4. 모델 직렬화

### Q1. `state_dict`로 저장한 `.pth` 파일을 불러올 때 모델 클래스 정의가 필요한 이유는 무엇입니까?

`state_dict`에는 모델 구조가 아닌 가중치가 저장되므로
동일한 모델 구조를 먼저 정의해야 합니다.

### Q2. `torch.jit.trace`와 `torch.jit.script`는 각각 어떤 상황에서 사용합니까?

`trace`는 실행 흐름이 일정한 모델에 적합하고,
`script`는 조건문이나 반복문 등 동적인 제어 흐름이 있는 모델에 적합합니다.

### Q3. ONNX의 가장 큰 장점은 무엇입니까?

특정 딥러닝 프레임워크에 종속되지 않고
다양한 플랫폼과 추론 환경에서 모델을 실행할 수 있다는 것입니다.

### Q4. `dynamic_axes`를 지정하지 않으면 어떤 문제가 생길 수 있습니까?

입력 크기가 고정되어 다른 배치 크기나 입력 크기를 처리하기 어려울 수 있습니다.

# 5. Day 1 최종 체크포인트

## Q1. 모델 학습과 모델 배포의 핵심 차이는?

모델 학습은 데이터를 이용하여 모델의 파라미터를 학습하는 과정이고,
모델 배포는 학습된 모델을 실제 사용자가 사용할 수 있도록 서비스하는 과정입니다.

## Q2. "내 컴퓨터에서는 되는데" 문제의 근본 원인은?

컴퓨터마다 Python 버전, 라이브러리 버전 및 실행 환경이 다르기 때문입니다.

## Q3. 가상환경을 사용하지 않으면 어떤 문제가 발생합니까?

프로젝트 간 라이브러리 버전과 의존성이 충돌할 수 있습니다.

## Q4. `pip freeze`와 직접 작성한 `requirements.txt`의 차이는?

`pip freeze`는 현재 환경 전체를 기록하고,
직접 작성한 `requirements.txt`는 프로젝트에 필요한 핵심 의존성을 관리합니다.

## Q5. 모델 추론 요청에 POST를 사용하는 이유는?

입력 데이터를 HTTP Request Body를 통해 서버로 전달하기 적합하기 때문입니다.

## Q6. 상태 코드 200, 400, 500의 의미는?

- `200` : 정상 처리
- `400` : 잘못된 요청
- `500` : 서버 내부 오류

## Q7. `state_dict` 방식은 왜 모델 클래스 정의가 필요합니까?

가중치만 저장되어 있고 모델 구조는 저장되어 있지 않기 때문입니다.

## Q8. ONNX의 가장 큰 장점과 사용 시점은?

다양한 프레임워크와 실행 환경에서 사용할 수 있다는 것이 장점이며,
PyTorch 모델을 다른 플랫폼이나 추론 엔진에서 실행해야 할 때 유용합니다.

## Q9. 모델 저장 전에 `model.eval()`을 호출해야 하는 이유는?

Dropout, Batch Normalization 등을 학습 모드에서 추론 모드로 전환하기 위해서입니다.

## Q10. `predict()` 함수를 별도 모듈로 분리한 이유는?

API 코드와 모델 추론 코드를 분리하여
재사용성과 유지보수성을 높이기 위해서입니다.
